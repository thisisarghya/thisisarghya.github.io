0. Context

Before diving into the mechanics of the PDA algorithm, it is important to establish the traditional framework of online algorithms and contrast it with the more recently developed ML-advised paradigm.

Traditionally, an online algorithm is defined by its lack of futuristic knowledge. It must serve an input sequence of requests sequentially—making irrevocable decisions and modifying the system state for each request before moving on to the next. Because it operates entirely without foresight, its performance is typically measured using a framework called competitive analysis, where the online algorithm's cost is compared against an optimal offline algorithm (OPT) that has full access to the entire future request sequence.

Recently, a new direction has emerged in the study of online algorithms: the Machine Learning (ML) advice model. These algorithms are referred to as learning-augmented or ML-advised algorithms or algorithms with predictions. In this modern framework, the strict assumption of zero futuristic knowledge is relaxed. Instead, the online algorithm is augmented with an "advisor" or "oracle"—often a trained machine learning model—that provides predictions about future requests. The algorithm can then incorporate this potentially faulty advice into its online decision-making process, aiming to achieve performance that surpasses traditional deterministic lower bounds when predictions are accurate, while maintaining robustness when the advice fails.

1. Introduction to the List Update Problem

In the list update problem, the input is an online sequence of access requests to items in a static linked list. To serve a request to an item at position \(i\), an online algorithm makes a linear scan of the list until it finds the item; this linear scan has an access cost of \(i\). After accessing the item, the algorithm may or may not reorganize the list to minimize the total cost of future accesses. For this, an algorithm has two choices for a reorganization of the list, i.e., two types of operations at its disposal:

  • Free Exchange: Moves the currently accessed item anywhere closer to the front of the list with a cost of 0.
  • Paid Exchange: Swaps the positions of any two consecutive items in the list with a unit cost of 1. The algorithms can make any number of paid exchanges
Given an input request sequence, a list update algorithm's objective is to maintain the list in a way that minimizes the total cost (i.e., the sum of costs for all accesses and paid exchanges).

While early literature assumed an optimal offline algorithm (OPT) would never perform paid exchanges, Reingold and Westbrook disproved this. For example, if the initial list is (1,2,3) and the request sequence is <3,2,2,3>, any algorithm using only free exchanges pays a cost of at least 9. However, by paying a cost of 2 upfront to execute two paid exchanges and alter the list to (2,3,1), the total cost reduces to 8.

State-of-the-Art Algorithms

Without futuristic knowledge, algorithms must rely on online heuristics. Move-To-Front (MTF), which moves an accessed item to the front of the list using a free exchange, is 2-competitive and is the best a deterministic algorithm can achieve. Other deterministic approaches like Frequency Count (FC) and Transpose fail to achieve a constant competitive ratio. Randomized algorithms (such as Bit, Comb, and Random-Reset) assign probabilities to confuse adaptive adversaries, achieving competitive ratios hovering between 1.6 and 1.75.

2. The Penalty Distance Algorithm (PDA)

We consider the classic list update problem under a prediction setting, where, upon accessing any item \(x\), a possibly faulty oracle predicts the next two times (indices in the input sequence) where \(x\) is requested again. We design a prediction model where the list update algorithm has access to predictions concerning the next two occurrences of the requested item in the request sequence. We refer to this algorithm as Penalty Distance Algorithm (PDA).

2.1 Algorithmic Mechanics

As each request is served, the list goes from one state to another through some paid exchanges and free exchanges. For that, PDA considers every possible configuration (ordering) of the list and computes two types of costs for each configuration, which we refer to as distance and penalty costs. PDA chooses the configuration that minimizes the sum of the penalty and the distance.

  • Penalty Cost: The idea behind penalty cost is to maintain an ideal configuration of the list that is aligned with an optimal ordering for lists of length 2 formed by the requested item and other items. Any violation of the ideal ordering in the above scheme translates to one unit of "penalty" in the PDA algorithm. For each possible configuration \(C\) of the list, it computes the number of items whose ordering with \(x\) in \(C\) is not ideal.
  • Distance Cost: PDA also computes the distance of \(C\) from the current configuration, defined as the minimum number of free and paid exchanges to convert the current configuration of the list to \(C\).

Ideal Ordering Logic (2-Item Cases)

Suppose \(b\) is the requested item, and let \(a\) be any item. If the current ordering is \((a, b)\), and the next three requests are predicted to be \((b, b, a,...)\), then \(a\) should be located after \(b\) in an ideal list. On the other hand, if the next three requests are predicted to be \(\langle a,a,b,\cdot\cdot\cdot\rangle\), then \(a\) should be located before \(b\) in an ideal list.

For lists of two items, correct predictions about the next request ensure optimality via a simple algorithm that only uses free exchanges: for a list formed by items \(a\) and \(b\), whenever there is a request to an item, say \(b\), in the second position, move it to the front if and only if the next request to \(b\) appears earlier than the next request to \(a\).

However, simple predictions about the next request reach their limit for lists of length 3. To make such decisions [regarding optimal free and paid exchanges], however, the algorithm requires the next two requests for each item.

3. Comparison: List Update vs. Caching (LRU)

The paper investigates the list update problem in light of the recent development for the caching problem under a prediction model. Both List Update and Caching are foundational problems in the analysis of online algorithms.

  • Similarity in Intuition: The Least Recently Used (LRU) algorithm for caching has a competitive ratio of \(k\) for a cache of size \(k\) [12]. Essentially, LRU and MTF both prefer to keep the recently used items handy.
  • The Critical Difference: The list update problem is NP-hard [2]. This is in contrast to the paging (caching) problem, where correct predictions about the next request ensure optimality via Belady’s rule (the simple algorithm that evicts the page that is requested furthest).
  • Limits of Prediction: While perfect lookahead guarantees optimality in caching, it does not do so for List Update when the list length \(N > 2\). Even if predictions are correct, we cannot hope for optimal solutions. As noted in Section 2.1, simple predictions about the next request are insufficient for list lengths of 3, potentially requiring paid exchanges to achieve optimality, which necessitates predictions about the next two requests for each item.

PDA seeks a consistent algorithm (good competitive ratio with correct predictions) that can be combined with Move-To-Front (MTF) to offer a Pareto-efficient solution that is robust when predictions are faulty.
