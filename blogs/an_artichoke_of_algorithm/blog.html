1. Introduction to the List Update Problem

In the list update problem [12], the input is an online sequence of access requests to items in a linked list. To access an item, an algorithm needs to linearly probe the list. Under the partial cost model, to access an element at index $i$, the algorithm pays a cost of $i - 1$. After accessing the item, the algorithm must reorganize the list to minimize the total cost of future accesses.

An algorithm can perform two types of operations during this reorganization:

  • Free Exchange: Moves the currently accessed item anywhere closer to the front of the list with a cost of 0.
  • Paid Exchange: Swaps the positions of any two consecutive items in the list with a unit cost of 1.

While early literature assumed an optimal offline algorithm (OPT) would never perform paid exchanges, Reingold and Westbrook disproved this. For example, if the initial list is (1,2,3) and the request sequence is $\langle 3,2,2,3 \rangle$, any algorithm using only free exchanges pays a cost of at least 9. However, by paying a cost of 2 upfront to execute two paid exchanges and alter the list to $\langle 2,3,1 \rangle$, the total cost reduces to 8.

State-of-the-Art Algorithms

Without futuristic knowledge, algorithms must rely on online heuristics. Move-To-Front (MTF), which moves an accessed item to the front of the list, is 2-competitive [12] and is the best a deterministic algorithm can achieve. Other deterministic approaches like Frequency Count (FC) and Transpose fail to achieve a constant competitive ratio. Randomized algorithms (such as Bit, Comb, and Random-Reset) assign probabilities to confuse adaptive adversaries, achieving competitive ratios hovering between 1.6 and 1.75.

2. The TwoHops / Penalty Distance Algorithm (PDA)

We consider the classic list update problem under a Machine Learning (ML) advice model. Upon accessing any item $x$, a possibly faulty oracle predicts the next two occurrences of the requested item in the sequence. We propose a learning-advised algorithm named TwoHops (conceptually referred to as the Penalty Distance Algorithm, or PDA).

2.1 Algorithmic Mechanics and Coloring

As each request arrives, PDA considers every possible configuration of the list and computes two types of costs: distance and penalty. To determine the ideal configuration, PDA assigns "colors" to items based on their predicted future occurrences relative to the requested item $x$:

  • Green Items: Items that should ideally appear before $x$. (e.g., if the prediction is $\langle a, a, x \rangle$, item $a$ is green).
  • Red Items: Items that should ideally appear after $x$. (e.g., if the prediction is $\langle x, x, a \rangle$, item $a$ is red).
  • Gray Items: Items where the relative order with $x$ does not strictly matter (e.g., $\langle a, x, a \rangle$ or $\langle a, x, x \rangle$).

PDA's objective is to use paid exchanges to bubble up green items before red items. The Penalty Cost measures how many violations exist in a given configuration (e.g., red items appearing before green items). The Distance Cost measures the minimum number of free and paid exchanges required to reach that configuration from the current state. PDA executes the sequence of exchanges that minimizes the sum of these two costs.

2.2 Examples of PDA in Action

Consider a list $L = \{a_1 \dots a_m, x\}$, where $x$ is the currently requested item at the end of the list:

  • All Red: If all items $a_1 \dots a_m$ are colored red, PDA moves $x$ to the absolute front of the list.
  • All Green: If all items $a_1 \dots a_m$ are colored green, PDA leaves $x$ at the end of the list and does not move it at all.
  • Mixed: If the first half of the list is green and the second half is red, PDA moves $x$ to the exact middle, cleanly separating the green items from the red items.

2.3 Conjecture 1 (Competitive Ratio)

We show that a special version, TwoHopsNoPaid, which restricts paid exchanges entirely, performs better than MTF and breaks the lower bound of 2 when predictions are correct.

Conjecture 1. When the prediction is correct, using the proper potential function for the analysis, we show the full PDA's competitive ratio is $\le 1.6$. If correct, the algorithm improves the best existing approximation algorithm with an approximation factor of 1.6 [6].

3. Comparison: List Update vs. Caching (LRU)

The paper investigates the list update problem in light of the recent development for the caching problem under a prediction model. Both List Update and Caching are foundational problems in the analysis of online algorithms.

  • Similarity in Intuition: The Least Recently Used (LRU) algorithm for caching has a competitive ratio of $k$ for a cache of size $k$ [12]. Essentially, LRU and MTF both prefer to keep recently used items handy.
  • The Critical Difference: The list update problem is NP-hard [2]. This is in contrast to the paging (caching) problem, where correct predictions about the next request ensure optimality via Belady’s rule.
  • Limits of Prediction: While perfect lookahead guarantees optimality in caching, it does not do so for List Update when the list length is greater than 2. Simple predictions about the next request are insufficient for list lengths of 3, potentially requiring paid exchanges to achieve optimality, which necessitates predictions about the next two requests for each item.

Ultimately, PDA provides a Pareto-efficient solution. It offers strong consistency (a near-optimal competitive ratio when predictions are correct) and can be combined with MTF to guarantee robustness (preventing unbounded costs when the ML oracle's predictions are faulty).
